# e2e-shards assigns every package under ./test/e2e/... and every top-level
# test in the top-level test/e2e package to exactly one CI shard. The table is
# read by scripts/e2e-shards, which also checks it against the packages and
# tests the go tool reports.
#
# Format, one shard per line:
#
#   shard <name> <package> [<package>...] -- [<test>...]
#
# Packages before "--" are the packages the shard runs. Tests after "--" are
# the top-level tests of the top-level test/e2e package that the shard runs;
# every other test in a listed package runs in that shard as well. A shard
# without a top-level test/e2e package needs no test list and runs every test
# in its packages.
#
# top-b is the catch-all shard: a new top-level test goes there unless it
# belongs with the tests in another shard. The coverage check fails until the
# new test is listed, so a test cannot silently drop out of the gate.
#
# The split follows the slowest-test reports of CI runs 44946061099,
# 44954331524, 44957914658, 44959458729 and 44962755194 on main. top-b was the
# longest shard at 260-300 s, mostly from two waiting tests: TestCardRenewedDaily
# (55.5-55.9 s) and TestLocalRegistration (34.4 s). Both drive local processes
# rather than containers, so they now run in the system shard, where they
# overlap with the system package's own 165-235 s and do not lengthen it. The
# two top-level shards keep the remaining tests, all below 16.7 s, beside the
# helper packages: top-b still runs those, whose slowest test (harness
# TestBuildBinaryCachesAndInjectsVersion) took 32.9-36.3 s in the same reports.
# Expected wall times after the move: top-a 226-247 s (unchanged), top-b
# 170-210 s, system 199-264 s (unchanged).
